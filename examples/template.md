## 02 AI Agent到底是什么

## 从 ChatBot 到 Agent：三种形态的区别

| 维度 | ChatBot | 服务端Agent | 桌面端Agent |
| --- | --- | --- | --- |
| 核心目标 | `回答问题`、生成内容 |  嵌入`业务流程`，稳定复用 | 在真实工作环境中`完成任务` |
| 任务形态 | 一问一答、即时响应 |  流程化、标准化、可部署 | 个性化、上下文强、执行深 |
| 适合场景 | 问答、写作、总结 | 知识库、数据查询、业务自动化 | 办公自动化、写代码、写报告、文件处理 |
| 角色类比 | `高级顾问` |  `流程经理` / `数字员工` |`个人助理` |

## 工作机制

[] **AI 大模型 —— `「大脑」`**：理解目标、规划路径、推理判断、动态调整
[] **Agent 工具 —— `「身体与感官」`**：读取文件、访问网页、调用系统、执行与反馈
[] **规则与上下文 —— `「边界」`**：告诉它能做什么、不能做什么、按什么标准做
[] **验证与反馈 —— `「方向盘」`**：发现偏差、及时拉回、持续修正


## 03 如何使用AI Agent

## 推荐使用路线

:: **入门选手 —— WorkBuddy**：低门槛，适合先把办公任务跑起来
:: **进阶选手 —— Claude Code + GLM / DeepSeek**：适合写脚本、做小工具、处理文件和数据
:: **魔法选手 —— Claude Code + Opus 或 Codex + GPT**：适合复杂任务、产品规划和大型项目开发


## 不要把什么工作都丢给Agent

- **适合脚本**：规则固定、输入明确、输出稳定、重复执行
- **适合 Agent**：目标明确、过程不确定、需要判断、需要调整
- **典型误区**：把批量改名、字段校验、固定报表这类任务，每次都交给 Agent 重新思考
- **正确方式**：先让 Agent `探索流程`，跑顺后`沉淀`成脚本、模板或固定工作流

## 清晰的目标和约束

- **目标清楚**：任务尽可能详细，而不是一句话需求
- **材料完整**：背景、文件、数据、参考样例要给足
- **边界明确**：哪些不能做、哪些不能碰、哪些必须遵守
- **验收具体**：做到什么程度算完成，怎么判断结果可用

## 重视Agent的Coding能力

- **数据分析**：批量处理文件、报表制作、数据分析
- **应用工具**：把重复流程自动化、个性需求工具化
- **不是程序员专属**：普通人也可以用它解决自己的问题
- **关键不是写代码**：而是指挥Agent去实现需求

## 我们的工作方式会发生哪些变化

:: **从亲自执行到指挥执行**：人负责定义目标，Agent 负责推进任务
:: **从经验驱动到规则沉淀**：把经验/流程写成模板、脚本、Skill 和工作流
:: **从等待支持到自助构建**：普通员工也能先做出小工具、小页面、小自动化
:: **从结果产出到质量把关**：AI 负责生成，人负责判断、修正和负责

## 一句话总结

> AI Agent 不会简单替代人，但会改变人的工作方式。人从`执行者`，变为定义目标、指挥行动、把关结果的`管理者`。
